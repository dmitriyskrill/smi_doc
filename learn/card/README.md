# Конспект визитки

Пути к файлам в этих заметках относятся к репозиторию `it_smi-server`. Сравнение с каталогом профилей лежит в [../compare](../compare).

Папка накапливает понимание по ходу визитки. Отсюда должно быть ясно, как устроена каждая применённая технология, какой сделан выбор и почему.

Исходная точка:

- Express — основной опыт. Привычны маршруты, middleware, `req`/`res`, свой JSON на каждый path.
- NestJS — только REST: модуль, контроллер, сервис, DTO, пайпы.
- GraphQL — новый. Его и смежные приёмы (field resolver, свой batch loader, code-first, Prisma через adapter-pg) конспект разбирает от уже знакомого.

## Два документа, две аудитории

| Документ | Для кого | О чём |
| --- | --- | --- |
| корневой `README.md` | проверяющий тестовое | архитектура и причины, коротко |
| `learn/` | автор | тот же выбор, разложенный от Express и Nest REST к файлам репозитория |

Корневой `README.md` конспект не заменяет. Конспект не подменяет обоснование для проверяющего. Если README сервера и код разошлись, для этих заметок верен код.

## Как пополняется

На каждое решение и на каждый новый механизм появляется или обновляется заметка. Пять вопросов:

1. Что выбрано.
2. Какой механизм Express или Nest REST это продолжает.
3. В чём отличие.
4. Почему так в этой визитке.
5. Чем платим и в каком файле это лежит.

Пока кода нет, у заметки статус «решение принято». Когда файл появляется, в заметку дописывается путь. Фрагмент кода берётся из репозитория, а не из памяти о том, как «обычно делают».

Чужие учебники сюда не копируются. Пишется только то, что реально работает в этой визитке и что нужно уметь объяснить на собеседовании.

## Состав

- [bridge.md](bridge.md) — как запрос, который ты раньше вёл маршрутом Express или контроллером Nest, идёт через GraphQL, с именами функций текущего кода.
- [decisions.md](decisions.md) — принятые решения, обоснование, цена и пути файлов.
- [Fastify_vs_Express_for_GraphQL.md](Fastify_vs_Express_for_GraphQL.md) — Sandbox, один маршрут `/graphql`, Apollo, Express и Fastify: почему адаптер остаётся Express.
- [technologies.md](technologies.md) — что уже разобрано по каждой технологии и какие файлы это держат.

## Готовность автора

Технология считана своей, когда вслух, без конспекта, получается четыре вещи:

1. Пройти путь одного запроса из Sandbox до чтения Prisma и обратно.
2. Назвать файл, в котором живёт механизм.
3. Сказать, почему выбран этот приём и чем за него заплатили.
4. Показать, какие файлы изменятся, если на собеседовании добавят одно поле.

Чекбокс «могу вслух» в [technologies.md](technologies.md) ставишь сам, после того как проговорил это на коде.
